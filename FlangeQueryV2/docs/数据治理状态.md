# 数据治理状态（3.1 立信阶段）

> 对应版本：3.8.1（数据治理框架 + 4.0 架构）
> 原则：**不把未核对的数据标成“已核对”**。每个标准/数据文件必须有来源与复核状态，缺口必须在应用内可见。

## 一、复核状态定义

| 状态 | 含义 |
|---|---|
| 已核对 `verified` | 数据来自对应标准 PDF 全文录入，可追溯到版本与表号 |
| 部分核对 `partial` | 数据已录入，但未逐条对照正式 PDF；或只覆盖部分型式/口径 |
| 推断/补全 `inferred` | 来自公开标准表、网络转写或经验推断，必须复核后才能用于正式出图 |
| 来源待复核 `alias` | 页面复用了其他标准的数据（当前 GB/T 9124.1/2 复用 HG/T 20592/20615） |
| 说明性数据 `descriptive` | 密封面型式说明，不是尺寸表 |
| 未收录 `missing` | 标准尚未建立数据表 |

## 三、界面与导出

- 每个页面标题下方显示：`数据来源 …` 与 `复核状态：状态 · 说明`；
- **行级**：加载时为每行附加 `review_status`、`复核状态`、`数据来源`；
- 表格第一列显示复核状态，颜色区分 verified/partial/inferred/alias；
- 行内已有复核字段时优先使用行值，否则继承文件级状态；
- CSV/XLSX 导出保留每行 `数据来源`、`复核状态`；
- `Data/manifest.json` 每个文件带 `review` 字段；`Data/data.db` 的 `manifest` 表同样保存；
- GB/T 9124 页签额外显示“复用 HG/T 20592/20615”的醒目提示。
