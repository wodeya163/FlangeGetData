# PySide6 迁移评估（FIX-20）

> 评估时点：2026-10-22，对应 FlangeQuery 3.1.0（PyQt5 5.15.11 + Python 3.13）
> 结论：**3.x 继续使用 PyQt5；在对外分发或需要 Qt6 能力时，再启动 PySide6 迁移。**

## 一、为什么要评估

| 维度 | PyQt5 | PySide6 |
|---|---|---|
| 许可 | GPLv3 / 商业双许可 | LGPLv3（更利于闭源分发） |
| Qt 版本 | Qt 5.15 | Qt 6.x |
| 高 DPI | 需手动开启属性 | Qt6 默认启用 |
| 官方支持 | Riverbank 维护 | Qt 官方 |
| 现有代码 | 已深度使用 | 需迁移 |

当前程序为内网/单机工具；若不对外分发，GPL 义务通常不触发。一旦随产品交付客户或合作方，许可与 Qt6 兼容性会成为迁移理由。

## 二、代码影响面

1. 导入路径：`PyQt5.*` → `PySide6.*`（约 10 个文件、几十处）；
2. API 差异：
   - `exec_()` → `exec()`；
   - `QAction` 从 `QtWidgets` 移到 `QtGui`；
   - `QRegExp`、`QDesktopWidget` 等 Qt5 专有类需要替换（当前项目未使用）；
   - 信号/槽、QPainter、QPrinter 基本兼容；
3. `QPrintPreviewDialog` 在 QtPrintSupport 中仍可用，但纸张/坐标行为需要回归；
4. 样式表（QSS）大多兼容，个别 Qt5 伪状态需要检查；
5. 测试：现有 51 个 unittest 可复用，但 `QT_QPA_PLATFORM=offscreen` 下的字体/插件行为需重新确认。

## 三、打包影响

- PyInstaller 需要 PySide6 钩子；Qt6 插件目录结构与 Qt5 不同；
- 体积预计增加 30–60 MB；
- Windows 10 及以上；官方 Qt6 不再支持 Win7/8；
- 现有 `FlangeQueryV2.spec` / `_onedir.spec` 需要调整 hiddenimports 与 datas。

## 四、工作量评估

| 阶段 | 内容 | 估算 |
|---|---|---|
| 试点 | 分支替换导入，跑通主窗口 + 1 个页面 | 3–5 人日 |
| 全量迁移 | 全模块 API 修正、打印、导出、绘图 | 1–2 周 |
| 回归 | 51 个测试 + 69 页人工抽检 + 打包验证 | 3–5 人日 |
| 发布 | 安装包、签名、体积/启动时间对比 | 2–3 人日 |

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| Qt6 打印坐标/分页差异 | 保留 PDF 回归样例，逐页比对 |
| 高 DPI 下固定像素布局 | 迁移前先完成自适应布局（FIX-03 已开始） |
| 第三方钩子不完整 | 先在 onedir 验证，再开 onefile |
| 体积增大 | 继续 onedir 为主，按需裁剪 Qt 插件 |
| 迁移期间功能冻结 | 单独分支，不阻塞 3.x 维护 |

## 六、建议

1. **暂不迁移**：3.x 继续 PyQt5，先把数据可信度与矢量绘图做完；
2. **触发条件**：对外商业分发、需要 Qt6 高 DPI/图形能力、或 PyQt5 停止维护；
3. **迁移顺序**：先 `flange_export`/`drawing` 等无 UI 模块，再 `main.py`；每步跑全量测试；
4. **保留回退**：迁移分支通过全部回归前，不合并到主线。
